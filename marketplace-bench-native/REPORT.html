Local benchmark · native-execution track · sibling to ../marketplace-bench

Take the EVM shim off the DAG chains, and the DAG advantage shows up

The original comparison (marketplace-bench/REPORT.html) tested Conflux and Hedera through their EVM-compatibility layers — eSpace and the Smart Contract Service — and found no DAG advantage. That's not a DAG result; it's an EVM-shim result. This track re-runs the same marketplace lifecycle through each DAG chain's native execution environment instead: Conflux Core Space (Solidity on the Conflux VM, not the EVM), Sui (Move), and Hedera (native Token Service + atomic transfers, no smart-contract VM at all). Besu stays as the linear baseline, unmodified — Solidity/EVM already is native there.

Headline

Latency: two of three native DAG chains blow past linear — one doesn't

besuLocal (linear)confluxCore (DAG)sui (DAG)hedera (DAG)

Median time from submit to receipt/finality, n=25 per bar. Every pairwise comparison is significant at p<0.0001 (Mann-Whitney U, full table in analysis/output/mannwhitney_latency.csv) — the gaps here aren't noise.

Sui and Hedera are 7–13x faster than linear Besu. Median latency lands at 158–182ms on Sui and 281–290ms on Hedera, against 2094–2113ms on besuLocal. Besu's floor is structural: IBFT2.0 with a fixed 2s block period means every transaction waits for the next block regardless of load. Sui's parallel object-DAG execution and Hedera's asynchronous Byzantine fault-tolerant gossip protocol both reach finality without that fixed-period wait — this is the DAG architecture doing exactly what the theory predicts, once nothing EVM-shaped stands between the transaction and the chain's own execution engine.
Conflux Core Space is the slowest chain in this comparison — slower than linear Besu on every operation (2532–2544ms vs. 2094–2113ms), and nearly identical to its own eSpace numbers from the original EVM-shim comparison. That's the important negative result: removing the EVM layer did not fix Conflux's latency, which means the EVM shim was never the bottleneck for this specific chain. Conflux's Tree-Graph/GHAST consensus is probabilistic-finality, not instant-finality like Sui's or ABFT-style like Hedera's — on a single local node with this devnet's confirmation-depth requirements, waiting for enough Tree-Graph confirmations to call a transaction final costs about as long as Besu's fixed block period, EVM or no EVM. The user's original hypothesis (EVM shim hides the DAG advantage) is confirmed for two of three chains and specifically not confirmed for Conflux — a real, chain-specific finding, not a rounding error.

Cost

Real, non-zero fees on every chain — but not directly comparable across currencies

Each chain's local devnet was verified to charge a genuine, non-zero fee (the original comparison's headline caveat — besuLocal's --min-gas-price=0 genesis silently zeroing cost data — is the exact failure mode every leg here was built to avoid; see each chain's README for how it was verified). Costs are reported in each chain's own native unit; converting to a common currency would need live market rates for CFX/SUI/HBAR/ETH that a local devnet has no meaningful equivalent of, so this deliberately doesn't force a single "cheapest chain" number.

Native vs. shim, chain by chain

What changed by removing the EVM layer

confluxCore

Contracts unchanged, execution environment changed. The Solidity byte-for-byte identical to marketplace-bench/contracts/ compiled and ran on the Conflux VM with zero source edits — Core Space has been EVM-opcode-compatible since the Hydra upgrade. The delta is CoreSpace's own account model, storage-collateral economics, and js-conflux-sdk instead of ethers/eSpace. Latency didn't move (see above) — the EVM-vs-native distinction turned out not to be where Conflux's bottleneck lives.

sui

Full rewrite in Move. Object-ownership model replaces Solidity's account/mapping model entirely — items are owned Move objects, listings are shared objects wrapping them, buy is an atomic coin-for-object swap with no allowance step ever needed. This is the purest native-DAG leg in the comparison, and it shows the largest latency win.

hedera

No smart-contract VM used at all. HTS handles the NFT lifecycle and a single atomic TransferTransaction handles buy — both-legs-at-once (NFT out, HBAR in) with no contract code, no gas metering, and no allowance-then-separate-transfer round trip. This atomic multi-asset transfer is a genuinely native DAG capability that none of the other three chains in this comparison can express without a contract call.

Process notes

What broke this pass, and how it was fixed

Real infrastructure, real bugs — documented rather than smoothed over:

  • besuLocal got wiped mid-run. A scoped-teardown mistake (docker compose down -v against the whole shared compose file instead of just conflux-local) removed besuLocal's container and volume while its own seed run was in flight. Recreated from the unmodified marketplace-bench/docker/local/ config and rerun clean; the mistake is documented in conflux-core/README.md so it isn't repeated.
  • confluxCore buy reverted 7/30 on the first pass with ExceedStorageLimit — js-conflux-sdk passes cfx_estimateGasAndCollateral's estimate straight through as a hard cap with no safety margin. Fixed with a padded-limit helper (1.3x gas, 2x storage); rerun was 150/150 clean.
  • hedera-local-node's consensus container failed to start (Checking for application.properties presence ..... ERROR) — a stale bind-mount view under Docker Desktop for Windows. Fixed with a scoped --force-recreate --no-deps network-node, and two real hedera-local-node CLI bugs (a --composedir path-resolution bug, and a hardcoded port-8545 preflight check colliding with besuLocal) were patched around rather than worked past.
  • hedera buy failed on the first pass with SPENDER_DOES_NOT_HAVE_ALLOWANCE — an approved-NFT-allowance transfer requires the spender to be the transaction's payer, not just a co-signer. Fixed by making the marketplace account the payer.

Scope

What this does and doesn't cover

  • 1-node/1-validator baseline only on every chain, same as the original comparison — no node-count sensitivity data for the native track.
  • No cross-currency cost normalization. CFX/SUI/HBAR/ETH costs are each real and each in their own unit; there's no live market rate meaningful to a local devnet, so no single "cheapest chain" claim is made here.
  • Operation coverage differs by chain, deliberately — forcing a fifth op onto Sui or Hedera where no faithful native equivalent exists would have manufactured data instead of measuring it. See DESIGN.md and each chain's README for the exact mapping and rationale.
  • marketplace-bench/ (the original EVM-shim comparison) is untouched. This is an additive, sibling comparison, not a replacement — the two reports answer different questions ("EVM-compatible DAG vs. linear" vs. "native DAG vs. linear") and both are valid to keep.
