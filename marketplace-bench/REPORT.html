Metric 5 of 6

Finality: first receipt vs. confirmation depth

First-receipt latency is only part of the finality story. Besu's IBFT2.0 is a BFT protocol — once 2/3+ validators commit a block, it's final immediately, with no reorg risk. Conflux's GHAST gives probabilistic finality that firms up as the pivot chain deepens. So "time to receipt" flatters Besu here in a way that doesn't reflect real settlement guarantees.

besuLocalconfluxLocal

Reading this chart correctly

Besu's climb to depth 12 (~26s) is not a finality cost — it's just 12 more blocks at a fixed 2s period, with nothing left to wait for after the first commit. Conflux's climb to the same depth takes only ~10s, because its block period is 4× shorter (0.5s vs. 2s) — at matched confirmation depth, Conflux reaches it in less wall-clock time despite its slower first receipt. With only 1 node on each chain there's no real competing miner, so this doesn't measure actual reorg risk — it measures the wall-clock cost of waiting for depth, which is what a wallet or exchange actually pays.

Metric 6 of 6

Node-count sensitivity

The original baseline was 1 node per chain. Both multi-node clusters scaffolded in this repo were brought up for real this pass — Besu reached full 4-validator IBFT consensus (confirmed via ibft_getSignerMetrics showing balanced round-robin proposing); Conflux reached genuine 3-of-4-node consensus after three clean rebuilds all converged on the same 3 nodes and the 4th consistently failed its P2P handshake — a real, reproducible limit in this image version, reported honestly rather than forced.

Dead end, documented

Fantom Opera: why it's not in this comparison

Hard, unfixable blocker — not a config problem

Fantom's go-opera client was the natural second DAG candidate (Lachesis aBFT, real market gas, Docker-only — Hedera was ruled out earlier for needing Kubernetes, which isn't installed here). Two problems, verified against the actual source rather than assumed:

No official Docker image. fantomfoundation has zero published repositories on Docker Hub; the repo's own Dockerfile.opera is build-from-source only, never pushed by CI.

The EVM caps at the London hardfork. go-opera's opera/rules.go defines exactly three fork toggles — Berlin, London, Llr — with no Shanghai/Cancun option anywhere, confirmed identically across three refs (master, latest release v1.1.3-rc.5, develop-1.13.0). Its vendored go-ethereum is v1.10.8 (~September 2021), 1.5–2.5 years before PUSH0/MCOPY existed. A repo-wide search for those opcodes returns zero matches. This repo's contracts need Cancun's MCOPY (OpenZeppelin 5.x) — there's no genesis flag that fixes an opcode gap compiled into the interpreter itself.

Fantom's newer Sonic client does support modern EVM forks but is a different codebase/consensus stack, not the Lachesis DAG client this comparison calls for — substituting it would change what's being compared and wasn't pursued without separate sign-off.

Process notes

What broke this pass, and how it was fixed

  1. 1
    Besu multi-validator genesis generation failed silently on a Windows bind mount. besu operator generate-blockchain-config --to errored Output directory already exists against a never-before-existing directory; worked around by generating into a container-local path and copying out. Also needed MSYS_NO_PATHCONV=1 to stop Git Bash from mangling container-side paths, and python/py fallback since python3 resolves to a broken Windows Store stub here.
  2. 2
    Besu static-nodes format was subtly wrong three different ways: nodes listing themselves (rejected), CRLF line endings from python -m json.tool on Windows corrupting the port field, and compose hostnames instead of literal IPs (Besu's enode parser requires an IP). Fixed with a self-excluding peer list, LF-only output, and a fixed-subnet Docker network with static per-validator IPs.
  3. 3
    Conflux cluster's config mount path was wrong (/conflux/run/... vs. the image's actual /root/run/...), so the container silently fell back to a randomized default config every restart. Fixed the mount path, pinned each node's net_key (was regenerating randomly, breaking peer identity across restarts), and applied the same literal-IP fix as Besu.
  4. 4
    Conflux's 4th cluster node never joins, reproducibly, across three independent clean rebuilds — confirmed at the TCP layer (raw connectivity works) and the protocol layer (the bootnode's logs show zero trace of a handshake attempt from the stuck peer). Which peer fails varies between rebuilds, ruling out a peer-specific bug. Treated as a genuine image-version limitation and reported as such rather than forced — the README already flagged this topology as unvalidated.
  5. 5
    Geth's modern CLI removed in-process account unlocking (--unlock/--mine/--miner.etherbase all gone, replaced by an external Clef signer) — switched from the planned Clique PoA setup to --dev --dev.period 2 against a pre-initialized custom genesis, which preserves the custom chain ID/fork times/account funding Clique would have needed anyway.

Scope

What this does and doesn't cover

In scope, this pass

3 working chains (2 linear clients, 1 DAG), 2 node-count variants, real cost on all three, a throughput-vs-concurrency sweep, resource usage under load, and finality/confirmation-depth — all measured, not simulated. Every number above traces to a specific CSV in bench-output/.

Still not in scope

A second DAG-architecture chain (Fantom ruled out, Hedera needs Kubernetes not installed here). A price-controlled cost comparison (besuLocal's 5gwei vs. the others' ~1gwei aren't the same tier). Throughput sweep beyond mint only. Deeper finality samples (n=10) or real multi-miner reorg risk (single node per chain, so no genuine competing-fork test).
